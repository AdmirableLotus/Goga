── 5. GOGA_MISSION_ENGINE Flag Interaction ──────────────────────
  When GOGA_MISSION_ENGINE=false (default):
    - mission:start IPC throws "MissionEngine is disabled"
    - AgentLoop is the ONLY operator path for all chat/voice commands
    - MissionEngine code is loaded but never executed

  When GOGA_MISSION_ENGINE=true:
    - mission:start IPC works — MissionPage can start missions
    - Chat/voice commands STILL route to AgentLoop (orchestrator unchanged)
    - MissionEngine and AgentLoop are PARALLEL paths, not alternatives
    - No code in orchestrator.ts checks isMissionEngineEnabled()

  CRITICAL FINDING: The F0 report claim "AgentLoop is disabled" is WRONG.
  AgentLoop is ALWAYS the chat/voice operator path regardless of the flag.
  GOGA_MISSION_ENGINE only gates the mission:start IPC handler.
  The flag does NOT disable AgentLoop. It does NOT redirect chat to MissionEngine.

  browser.navigate       medium    true     false             risk medium within auto-approve threshold medium

  MUTATION BEFORE APPROVAL CHECK:
  AuthorizationService.evaluate() returns a decision object only.
  No mutation occurs inside evaluate(). Execution only happens after:
    AgentLoop: decision.requiresApproval → requestApproval() → await user → registry.execute()
    MissionEngine: decision.requiresApproval → requestApproval() → await user → registry.execute()
  Therefore: no medium/high/critical mutation can occur before explicit approval.
  EXCEPTION: autoApproveBelow="medium" means medium-risk tools execute WITHOUT approval.
  computer.type (medium) and computer.click (medium) execute without approval by default.
